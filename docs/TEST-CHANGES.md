# 测试身份与失败证据变化

比较报告新增 `test_changes` 和 `witness_changes`，以所提供的摘要为前提解释内容变化。常规比较仍不自动核验原始文件或历史运行来源。

## 匹配规则

先按内容摘要分组，再处理剩余的同名记录。测试的数组位置和运行记录顺序不参与匹配。

| kind | 含义 |
|---|---|
| unchanged | 两侧各有一份相同摘要，且 ID 相同 |
| renamed | 两侧各有一份相同摘要，但 ID 改变；包括测试编号互换 |
| ambiguous | 相同摘要在任意一侧重复，无法唯一配对；列出该摘要两侧全部 ID |
| modified | 唯一摘要未匹配，且相同 ID 在两侧仍各有一个未匹配记录；表示该命名位置的内容被替换 |
| removed | 旧记录没有内容匹配或可确定的同名替换 |
| added | 新记录没有内容匹配或可确定的同名替换 |

内容匹配优先于同名匹配。因此，如果旧编号 A、B 对应的内容在新版本交换，报告两个 renamed，而非两个 modified。重复摘要不通过相同编号强行配对。

modified 不是逻辑测试身份的证明。例如输入和答案只要任何原始字节改变，组合摘要就改变；当前格式不能区分究竟改了输入还是答案。保持同一命名位置仅作为可复查的替换关系。

## 失败证据

对两侧可通过唯一源码摘要匹配的解法，每份旧失败测试生成一条 witness_changes。记录旧测试 ID 和判定、内容变化类别，以及可以唯一确定的新测试 ID、当前判定。

- 删除测试时，新测试和新判定均为 null。
- 内容未变或改名时，可以关联新结果；新运行缺失时，新判定为 null。
- 同名替换的 content_status 为 modified；新结果属于替换后的内容，不能解释成旧失败测试已通过。
- 重复内容有歧义时不选择单个新测试，两个新字段为 null。

有失败证据消失，不一定意味着错解漏过。只有当前完整测试集全部通过，且解法、预期标签和比较条件符合已有规则，才报告相应的全局判定转换。数据、判题器、运行条件发生变化时，这些清单不自动建立因果关系。

只要出现非 unchanged 的测试变化，命令行就返回 1，表示需要审查。它不一定是判题错误；完整且无变化的比较才返回 0，输入错误仍为 2。
